Dockerfile
Why it's there
docker build: runs the lines top to bottom and creates the image
FROM node:22-alpine
→
Start from an image that already has Node. No need to install Linux or Node yourself.cached ⚡
WORKDIR /app
→
Give the app a home folder. Creates /app and runs the next lines inside it.cached ⚡
COPY package*.json ./
→
Copy only the dependency list first, so the install below can come from the cache.cached ⚡
RUN npm install
→
Install packages while building. The slow step, skipped if package.json didn't change.cached ⚡
COPY . .
→
Now copy your code. It changes most often, so it goes last. You edited App.tsx, so only this redoes.rebuilt
ENV NODE_ENV=development
→
A setting the app reads while it runs, like process.env.NODE_ENV.setting
EXPOSE 5173
→
A note that the app listens on 5173. It doesn't open the port; -p does that.setting
CMD ["npm", "run", "dev"]
→
What to run when a container starts. Not during the build.setting
docker run: every time, creates a container from the image

⚡ Why this order?

Docker reuses every layer until it reaches the first one that changed. Packages change rarely and code changes all the time, so install first and copy your code last. Editing a component then rebuilds in seconds.

🟢 What docker run does

Puts a thin writable layer on top of the read-only image, sets the ENV values and runs CMD. Delete the container and only that thin layer goes away. The image stays.

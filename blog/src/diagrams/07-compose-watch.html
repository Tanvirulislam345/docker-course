docker compose watch
Save a file and Compose updates the container
✏️ You save a file
→
👀 Compose checks the
develop.watch rules
→
⚡ It runs the matching action
compose.yaml
1services:
2  web:
3    build: ./frontend
4    develop:
5      watch:
6        # source code
7        - path: ./frontend
8          target: /app
9          action: sync
10        # new packages
11        - path: ./frontend/package.json
12          action: rebuild
13
14  api:
15    build: ./backend
16    develop:
17      watch:
18        # read once at startup
19        - path: ./backend/config.json
20          target: /app/config.json
21          action: sync+restart
syncL7–9
Use it for source code

Copies the changed file into the running container. Vite or nodemon notices and reloads.

edit App.jsx → file copied → page updates
rebuildL11–12
Use it for package.json, the lock file, the Dockerfile

Builds a new image and swaps the container, so new packages actually get installed.

npm install axios → new image → new container
sync+restartL19–21
Use it for config the app reads at startup

Copies the file, then restarts the container so the app reads it again.

edit config.json → file copied → restart

Without watch

Edit code, run docker compose up --build, wait. Every time. Bind mounts help, but they share everything (even node_modules) and never install new packages.

With watch

You decide which files to watch and what happens when they change. Code syncs in about a second, and Compose only rebuilds when it really has to.

Docker Compose anatomy
One file that describes your whole app
compose.yaml (simplified from mern-docker)
services:  web:                     # service = 1 container
    build: ./frontend       # build from Dockerfile
    depends_on: [api]
    ports:
      - 5173:5173          # host:container
    environment:
      VITE_API_URL: http://localhost:8000
  api:
    build: ./backend
    ports: ["8000:8000"]
    environment:
      DB_URL: mongodb://db/anime
  db:
    image: mongo:latest      # ready-made image
    volumes:
      - anime:/data/db     # keep the data

volumes:
  anime:                    # named volume

services

The list of containers your app needs. Each one gets its own container.

web / api / db + build

Service names. Pick any name — it also becomes the hostname on the network. build points to a folder with a Dockerfile.

ports

Same as -p 5173:5173. Left = your computer, right = container.

environment

Same as -e KEY=value. Settings your app reads at runtime.

image

Use a ready-made image from Docker Hub instead of building one.

volumes (in a service)

Same as -v. Mount a named volume or a folder into the container.

volumes (top level)

Declares named volumes. Compose creates them for you.
